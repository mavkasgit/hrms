# HRMS

Корпоративная система управления кадрами. Единый контекст: HR-оператор ведёт
жизненный цикл документов (приказы, уведомления, заявления) и связанных данных.

## Language

**Auth-shell (общий модуль входа)**:
Байт-идентичные с KTM-2000 файлы страницы входа и OIDC-клиента
(`features/auth/*`, `shared/api/client.ts`). Правки для двух сервисов делаются
в едином стиле: синхронно в обоих репозиториях, с поднятием `*_VERSION`
и проверкой `verify-sync` (ADR-0002).
_Избегай_: свой формат страницы входа, разветвление общего кода

**JIT-провижининг (JIT provisioning)**:
Автосоздание локального пользователя при первом входе по данным IdP
(id_token), когда локальной записи ещё нет. Гейт — флаг
`AUTH_OIDC_ALLOW_JIT`; роль берётся из claim IdP (`hrms_role`), fail-closed
(нет валидной роли → 403, пользователь не создаётся).
_Избегай_: авторегистрация, just-in-time provisioning

**Черновик (document draft)**:
Сохранённый, но ещё не ставший документом экземпляр приказа, уведомления или
заявления. Виден в списке черновиков (`/drafts`) и в счётчике сайдбара.
_Избегай_: draft, черновик формы

**Черновик формы (form draft)**:
Несохранённое заполнение формы создания документа, хранящееся локально в
браузере (localStorage). Восстанавливается в ту же форму, из которой было сделано.
_Избегай_: черновик, localStorage-draft

**Заполнить**:
Действие: заполнить форму создания данными черновика (документного или
форменного), чтобы пересоздать документ на основе сохранённых значений.
_Избегай_: восстановить, применить черновик

**Открыть**:
Действие: посмотреть документ черновика в режиме только чтения, без возможности
случайного сохранения или редактирования.
_Избегай_: просмотр, view

**Восстановить**:
Действие: открыть документный черновик в редакторе для доработки и последующего
сохранения в качестве полноценного документа.
_Избегай_: восстановить заполнение, reopen

**Удалить (delete_draft)**:
Действие: безвозвратно удалить черновик как таковой. Применимо только к объекту
в состоянии «черновик»; для БД-видов это означает удаление строки `is_draft=True`.
_Избегай_: сбросить, discard; удалить документ (это отдельное действие)

**Коммит черновика (commit)**:
Действие: перевести черновик в документ. У БД-видов — снять `is_draft`; у приказа —
создать `Order` и потребить черновик. Контракт общий, реализация перехода
принадлежит виду. Повторение успешного commit не является ошибкой (идемпотентность).
_Избегай_: «отправить», «подтвердить» (это не про переход черновика)

**Финализация (finalize)**:
Действие (только БД-виды): обновить файл черновика из OnlyOffice
(`download_and_replace`) и затем коммитить черновик. Композиция use-case'а,
а не отдельный примитив lifecycle; порядок — скачивание, затем коммит.
_Избегай_: «зафиналить» без уточнения, что это композиция из двух операций

**Потребление черновика (consume)**:
Следствие успешного commit: черновик перестаёт быть доступен как черновик.
У приказа черновик (файл/метаданные) удаляется, остаётся durable `Order`;
у БД-видов строка остаётся, но `is_draft=False`. Cleanup файлов — пост-коммитная
операция, повторяемая (retryable).
_Избегай_: «удаление приказа», «закрытие черновика»

**`source_draft_id`**:
Неизменяемый opaque-идентификатор источника, породившего `Order`; одновременно
используется как idempotency-ключ commit-пути. Не обещает обратной разрешимости
на существующий черновик (тот уже consumed) и не является FK на draft storage.
_Избегай_: «id черновика» (это presentation-`DraftRef`, другой концепт)

**Удалить документ (delete_document)**:
Отдельное действие: безвозвратно удалить уже созданный документ (`is_draft=False`
для БД-видов, `Order` для приказов). Не является частью lifecycle черновика —
отдельный use-case со своей авторизацией.
_Избегай_: «просто удалить» без различения черновик/документ

## Работа с документами в OnlyOffice

**Принудительное сохранение (forcesave)**:
Команда OnlyOffice сохранить текущее состояние документа из редактора
без закрытия. Исход — файл персистен, ошибка, или «без изменений» (no_changes).
_Избегай_: принудительная отправка, форсированное сохранение

**Статус сохранения (save status)**:
Дурабельный исход сохранения черновика (never/saved/error), показывается
бейджем в списках. Обновляется при callback OnlyOffice, переживает рестарт.
_Избегай_: статус попытки, save_state

**Попытка сохранения (save attempt)**:
Транзиентная запись одной команды принудительного сохранения
(pending/persisted/failed/no_changes), которую опрашивает редактор.
Живёт в in-memory tracker, не переживает рестарт.
_Избегай_: статус сохранения (это другое — дурабельный бейдж)

**Колбэк OnlyOffice (OnlyOffice callback)**:
HTTP-уведомление Document Server о состоянии документа (сохранение, ошибка,
закрытие). Нормализуется один раз в единый исход: persisted / failed / ignore.
_Избегай_: нотификация, вебхук OnlyOffice

**Идентичность соавтора (editor user)**:
`editorConfig.user` в конфиге редактора: `id` = username, `name` = full_name
(или username, если ФИО пусто). Передаётся всегда (edit и view), чтобы
OnlyOffice не показывал диалог ввода имени и не записывал анонимных
соавторов. `name` никогда не пустой — пустой `name` возвращает диалог.
_Избегай_: имя пользователя, coauthor display name

**Подсказки о нововведениях (features tips)**:
"what's new" попапы Document Server (8.2+), отключаются
`editorConfig.customization.features.featuresTips: false`. Отключаются
глобально через конфиг, без версие-гейтинга (зафиксирована 9.4.0).
_Избегай_: онбординг-модалки OnlyOffice, «новое» попапы

**Стадии загрузки редактора (editor load stages)**:
0–20с — ничего; 20с — мягкий хинт «Загрузка редактора…»; редактор готов —
хинт исчезает; 60с — жёсткая ошибка. Жёсткая ошибка также при скрипт-фейле,
отсутствии DocsAPI и onError. Хинт — last-resort совет про блокировщик,
а не первое сообщение.
_Избегай_: «сообщение о блокировщике», загрузочный алерт

## Аутентификация и сессии

**Аварийный доступ (break glass)**:
Вход в обход обычного процесса (OIDC/сессии) по env-паролю
(`BREAK_GLASS_*`), когда IdP недоступен. Не создаёт запись в `users` и
серверную сессию; токен помечается `is_break_glass: true`.
_Избегай_: emergency access, аварийный вход по паролю

**Сессия (server-side session)**:
Запись в `user_sessions`. Активный доступ проверяется по ней, а не по самому
JWT: JWT — лишь указатель (`sid`). Отзывается при logout/revoke.
_Избегай_: токен, JWT (это разные вещи)

**Claim `sid`**:
Всегда `UserSession.id`, только session-семантика. Если JWT содержит `sid`,
он ссылается на активную сессию пользователя. Токен без `sid` — не сессия.
_Избегай_: просто «идентификатор сессии» без уточнения инварианта

**История входов (login event)**:
Аудит-записи входа/выхода пользователя (`user_login_events`): login_success,
login_failure, logout, session_revoke. Окно показа — последние 10 по
`created_at DESC` (канон user-settings 2.1.0).
_Избегай_: audit log, события аудита

## Профиль

**Профиль**:
Display-поля пользователя: full_name, email, avatar_seed, locale, theme.
Источник правды — Authentik (IdP); локальная БД — только кэш.
_Избегай_: user profile, учётные данные

**Кэш профиля**:
Локальные копии display-полей в `users`. Пулл при `/me` пропускается, пока
кэш свеж (`profile_synced_at` в окне TTL).
_Избегай_: профиль в БД (это кэш, не SoT)

**`profile_synced_at`**:
Метка последнего авторитетного ответа IdP: профиль получен или «такого
пользователя нет». При упавшем пулле не обновляется.
_Избегай_: timestamp последней синхронизации (без инварианта «или нет такого»)

**`profile_sync_failed_at`**:
Метка последней упавшей попытки пулла. Инвариант: не чаще одной попытки
синхронизации профиля в окно TTL, успешной или нет.
_Избегай_: ошибка синхронизации (это метка, не событие)

## Отпуска

**Период отпуска (рабочий год)**:
Интервал от годовщины приёма (или корректировки) до следующей, с балансом
дней (main + additional). Баланс и операции периода ведутся в
`vacation_periods` / `vacation_period_transactions`.
_Избегай_: «год», «год отпуска»

**Остаток (периода отпуска)**:
Доступные дни периода. Для открытого — вычисляется как `total - used`;
для закрытого/частично закрытого — сохраняется явно (`remaining_days`).
_Избегай_: «свободные дни»

**Частичное закрытие (частично закрытый период)**:
Калибровка остатка периода оператором: оператор фиксирует, сколько дней
остаётся. Период **остаётся в очереди автосписания** (FIFO, старый → новый),
пока остаток не израсходован до 0. Пропускается при автосписании только
полностью закрытый (остаток 0).
_Избегай_: «заморозить период» (это было старое, неверное поведение)

**Полное закрытие (закрытый период)**:
Остаток 0 (`remaining_days == 0`). Период исключается из автосписания.
_Избегай_: «закрыт без остатка» без уточнения про 0

**Автосписание (auto-use)**:
Списание дней отпуска с периодов по FIFO (самый старый доступный первым),
без привязки к рабочему году, в который попадает дата отпуска.
_Избегай_: «списание по периоду отпуска»

## Инфраструктура разработки

**Test launcher**:
`scripts/test-run.ps1` — единственная точка входа в backend-тесты;
владеет жизненным циклом run-DB. Канон: `backend/tests/AGENTS.md`.
_Избегай_: «запустить pytest напрямую с `-n`» (без launcher параллель запрещена)

**Test Run**:
Один запуск тестов через launcher; идентифицируется `RUN_ID` (12 hex).
Каждый run получает собственную изолированную БД.
_Избегай_: общая тестовая БД на всех

**Run Database (run-DB)**:
Эфемерная БД `hrms_test_<runid>`, создаваемая launcher'ом на время одного
run. Дропается только своим прогоном; другие прогоны её не трогают.
_Избегай_: общий `hrms_test` для параллельных прогонов

**Orphan database**:
run-DB, осиротевшая из-за убитого прогона; убирается отдельной командой
`test:db:cleanup` по TTL. Не вычищается самим прогоном.
_Избегай_: «устаревшие БД», «мусорные БД» (это БД с owner-записью)

**Module schema**:
Схема `t_<uuid8>` на каждый тест-модуль внутри run-DB; изоляция данных между
модулями без CREATE DATABASE. Дропается в teardown модуля.
_Избегай_: per-module БД (старая модель)
