## What to build

Сохранение черновика как приказа читает данные с сервера (метаданные черновика), а не из памяти открытой вкладки. Отредактированный в редакторе документ переносится в постоянный файл приказа (существующее поведение сохраняется). Запись в базе и документ всегда согласованы.

Устаревшие черновики без метаданных отклоняются с понятным сообщением «Черновик устарел, создайте заново». Если сохранение упало, черновик не блокируется навсегда — повторная попытка возможна. Дублирующиеся/параллельные запросы сохранения одного черновика не создают второй приказ и завершаются без ошибки для пользователя.

## Acceptance criteria

- [ ] Коммит черновика создаёт приказ из серверных метаданных без повторной отправки формы с фронтенда
- [ ] Отредактированный в редакторе документ переносится в постоянный файл приказа
- [ ] Черновик без метаданных отклоняется с сообщением «Черновик устарел, создайте заново»
- [ ] При неудачном сохранении черновик остаётся доступным для повторной попытки
- [ ] Дублирующийся коммит одного черновика не создаёт второй приказ (тихо, без ошибки у пользователя)
- [ ] E2E-тест: сохранение приказа работает через серверные метаданные
