## What to build

Каждый черновик приказа хранит на сервере свои метаданные (payload создания: сотрудник, тип приказа, дата, номер, дополнительные поля) в дополнение к документу docx — тем же механизмом, который уже используется для групповых черновиков. В метаданных фиксируются создатель, время создания, статус и версия схемы.

Черновик становится самодостаточным: данные для восстановления и сохранения лежат на сервере и не зависят от вкладки, на которой черновик создали.

## Acceptance criteria

- [ ] При создании обычного черновика приказа метаданные сохраняются на сервере рядом с docx (формат и схема — как у групповых черновиков)
- [ ] Метаданные содержат полный payload создания, создателя, время создания, статус и версию схемы
- [ ] При ошибке сохранения метаданных черновик откатывается целиком — не остаётся docx без метаданных
- [ ] Тест API: у созданного черновика читаемые сервером метаданные

## Blocked by

None — can start immediately.
