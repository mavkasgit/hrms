# ADR-0004: Единый владелец фронтового auth-состояния — `useAuth`

Дата: 2026-08-08. Статус: принято.

## Контекст

Появился единый auth-контекст `AuthProvider`/`useAuth` (`features/auth/hooks/useAuth.tsx`,
общий модуль с KTM, ADR-0002), который тянет `/auth/me` и держит текущего пользователя.
Но сайдбар (`shared/ui/sidebar.tsx`, HRMS-only, в sync-манифест не входит) вёл
параллельный auth-state: ручной JWT-декод (`decodeToken` со спец-кейсом `token === "admin"`),
собственный `GET /auth/me` без `?refresh=1` и локальный `currentUser`-state с типом `any`,
плюс перезапрос профиля на каждую навигацию (`useEffect` на `location.pathname`).
Два источника правды о пользователе расходились и держали лишний сетевой трафик.

## Решение

Единственный владелец фронтового auth-состояния — контекст `useAuth()`.

1. Сайдбар удаляет `decodeToken`, локальный `currentUser` и собственный `GET /auth/me`;
   читает `useAuth().user` и `isLoading`. Пока `isLoading` — нейтральный плейсхолдер
   (авторизованный не видит кнопку «Войти»).
2. Обновление после смены профиля в диалоге настроек — через `useAuth().refreshUser()`
   (`?refresh=1`, обход TTL-кэша), а не собственный запрос.
3. Тему/локаль сайдбар больше не применяет: `AuthProvider` делает это сам через
   `authHostConfig.applyUserPrefs` при каждом изменении `user`, а диалог — мгновенно.
4. Сайдбар остаётся в `shared/ui` и читает контекст напрямую (сознательное нарушение
   FSD «shared не импортирует из features» — уже существующее для useAuth, диалога
   настроек и колокольчика). Вынос сайдбара в правильный слой (`features/layout`
   или `app/layouts`) — отдельный follow-up, не в этом тикете.

Файлы общего auth-shell (`useAuth.tsx`, `client.ts`) не меняются, версии модулей
не бампятся.

## Последствия

- Положительные: один источник правды, fail-closed при падении `/auth/me`
  (токены чистятся, показывается кнопка входа) вместо устаревшего пользователя
  из JWT-декола; уходит `currentUser: any`; минус лишний запрос на навигацию.
- Отрицательные/принятые риски: закреплённое нарушение FSD-границ в `shared/ui`
  (компенсируется follow-up по выносу слоя); во время `isLoading` вместо мгновенного
  пользователя из JWT — плейсхолдер.
