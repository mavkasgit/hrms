# ADR-0002: Общий auth-shell — правки в едином стиле для двух сервисов

Дата: 2026-08-08. Статус: принято; обязательная lifecycle-синхронизация
приостановлена до возврата двухпроектного паритета.

## Контекст

KTM-2000 и HRMS — два отдельных репозитория, но их фронтенды разделяют общий
**auth-shell**: страница входа, OIDC-клиент, auth-контекст и API-клиент
(`frontend/src/features/auth/*`, `frontend/src/shared/api/client.ts`). Файлы
помечены в `scripts/sync-manifest.json` как `must-match`; архитектурное правило
байт-идентичности сохранено, но сейчас проверяется только явно запуском
`npm run verify:sync`.

Раньше это было только конвенцией в комментариях шапок файлов. Практика
показала, что правки легко применить только в одном репозитории, после чего
`prebuild`-гейт ломается, а визуально сервисы расходятся (кнопки, тексты,
поведение страницы входа).

## Решение

Любая правка, затрагивающая оба сервиса, выполняется в **едином стиле**:

1. Общий модуль правится в едином стиле в обоих репозиториях, а версии его
   копий синхронизируются при возврате к межпроектному паритету.
2. Версия модуля (`*_VERSION`) поднимается одновременно во всех его копиях:
   в самом файле и в дублях хостовых конфигов (`authHostConfig.ts`,
   `oidcHostConfig.ts`).
3. Визуальные элементы (кнопки, тексты, layout) страницы входа одинаковы в
   обоих сервисах. Бренд-различия — только через хостовые конфиги
   (имена, storage-префиксы, словари), не через разветвление в общем коде.
4. Документация общего модуля (ADR, глоссарий) ведётся синхронно в обоих
   репозиториях. В `sync-manifest.json` она не включается: номера ADR
   у репозиториев разные, поэтому байт-идентичность для них неприменима.

## Последствия

- Положительные: общее происхождение кода входа и один стиль изменений
  сохраняются; ручной `verify-sync` позволяет проверить паритет перед
  возвратом обязательного enforcement.
- Принятые риски: расхождение общей копии временно не блокирует `npm run dev`
  и сборку; при возврату паритета нужно восстановить автоматический гейт.
